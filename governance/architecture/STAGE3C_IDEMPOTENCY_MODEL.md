# Stage 3C Idempotency Model

**Status:** PLANNING (Stage 3C.0)
**Parent:** Stage 3C Architecture Specification

## Overview

Idempotency ensures that a mutation is applied exactly once, even if the runtime retries due to network failures or ambiguous responses. Every mutable provider operation carries an idempotency key, and the runtime rejects detectable replays before they reach the provider.

## Idempotency Key Generation

### Key Structure

```
idem-<executionId>-<operationHash>-<attemptNumber>
```

| Component | Source | Example |
|---|---|---|
| `executionId` | ExecutionRequest.executionId | `s3b-q-20260718-abc123` |
| `operationHash` | Deterministic hash of operation parameters | `a1b2c3d4` |
| `attemptNumber` | Monotonic counter per execution | `1` |

### Generation Rules

1. The key is generated by the `CredentialManager` or a dedicated `IdempotencyKeyGenerator` at the last responsible moment before the provider call
2. The `operationHash` is computed from stable-JSON-serialized operation parameters (sorted keys, no whitespace)
3. The `attemptNumber` increments on each retry, allowing the provider to distinguish a replay from a genuinely new attempt
4. The key is deterministic for the first attempt; it becomes non-deterministic only on retry (attemptNumber changes)

### Google Calendar Implementation

For `events.insert`, the operation parameters include:
```json
{
  "summary": "Team standup",
  "start": {"dateTime": "2026-07-20T09:00:00", "timeZone": "America/New_York"},
  "end": {"dateTime": "2026-07-20T09:30:00", "timeZone": "America/New_York"}
}
```

The `operationHash` = deterministic hash of the above JSON. If any parameter changes, the hash changes, producing a different idempotency key.

## Replay Detection Architecture

```
┌──────────────────────────────────────────────────────────┐
│                    IdempotencyStore                        │
│                                                           │
│  put(key, status): Store idempotency key with status      │
│  get(key): Retrieve stored execution for a key            │
│  isReplay(key): Check if key has been seen before         │
│  complete(key, result): Mark key as COMPLETED             │
│  fail(key, error): Mark key as FAILED                     │
│  cleanup(olderThan): Remove entries older than TTL        │
└──────────────────────────────────────────────────────────┘
```

### State Machine

```
NOT_SEEN ──→ EXECUTING ──→ COMPLETED
                 │              │
                 └──→ FAILED ───┘
```

| State | Meaning | Duration |
|---|---|---|
| `NOT_SEEN` | Key never encountered; proceed with execution | N/A |
| `EXECUTING` | Execution in progress; return "in progress" status | Up to 30 seconds |
| `COMPLETED` | Execution completed; return cached result | TTL: 24 hours |
| `FAILED` | Execution failed; allow retry with new attemptNumber | TTL: 24 hours |

### Replay Handling

| Scenario | Detection | Action |
|---|---|---|
| Same key, same execution, already COMPLETED | Key found in COMPLETED state | Return cached result; NO provider call |
| Same key, same execution, currently EXECUTING | Key found in EXECUTING state | Return `409 Conflict` with `retryAfter` hint |
| Same key, same execution, FAILED | Key found in FAILED state | Allow retry with incremented attemptNumber |
| Different key for same logical operation | Different key | Treat as new execution (cannot detect) |

### Storage Backend

| Environment | Backend | Rationale |
|---|---|---|
| In-memory (dev/test) | `Map<string, IdempotencyEntry>` | No external dependency for testing |
| Production | Redis with TTL | Atomic operations, built-in TTL, persistence |

## Idempotency in the Orchestration Flow

```
S3B_EXECUTION phase:
  1. Generate idempotencyKey (executionId + operationHash + attemptNumber)
  2. IdempotencyStore.get(idempotencyKey)
     ├─ COMPLETED → return cached result; skip provider call
     ├─ EXECUTING → return 409; caller may backoff
     └─ NOT_SEEN / FAILED → continue
  3. IdempotencyStore.put(idempotencyKey, EXECUTING)
  4. Adapter.execute(request, candidate)  ← real provider call
  5. On success: IdempotencyStore.complete(idempotencyKey, result)
  6. On failure: IdempotencyStore.fail(idempotencyKey, error)
  7. On ambiguous: IdempotencyStore.put(idempotencyKey, EXECUTING) (keep locked)
```

## Provider-Level Idempotency

### Google Calendar Support

The Google Calendar API does not natively support idempotency keys in request headers. Idempotency is achieved at the application layer:

- **Before execution**: Check if an event with the same idempotency key (stored as an extended property or custom field) already exists
- **After ambiguous response**: Read back the event list to determine if the mutation was applied
- **Comparison key**: Store `idem-<executionId>-<hash>-1` as an event extended property for server-side correlation

### Conditional Requests

Where the provider supports it, use HTTP conditional headers:

| Header | Use Case |
|---|---|
| `If-None-Match` | Only create if event does not exist (etag-based) |
| `If-Match` | Only update if event version matches (etag-based) |

## TTL and Cleanup

| State | TTL | Rationale |
|---|---|---|
| EXECUTING | 60 seconds | Covers maximum expected execution time |
| COMPLETED | 24 hours | Covers retry windows and delayed verification |
| FAILED | 24 hours | Covers retry windows for operator intervention |

## Audit Events

| Event | Trigger |
|---|---|
| `IDEMPOTENCY_HIT` | Replay detected; cached result returned |
| `IDEMPOTENCY_EXECUTING` | Key marked as executing |
| `IDEMPOTENCY_COMPLETED` | Execution completed key |
| `IDEMPOTENCY_FAILED` | Execution failed key |
| `IDEMPOTENCY_AMBIGUOUS` | Ambiguous outcome; key remains locked |

## Rejected Approaches

| Approach | Reason |
|---|---|
| UUID-based idempotency keys | Non-deterministic; cannot derive key from operation |
| Provider-native idempotency (Google) | Google Calendar does not support native idempotency keys |
| All retries use same key | Provider might partially apply mutation on first attempt |
| No idempotency store | Risk of double-mutation on network timeout |
